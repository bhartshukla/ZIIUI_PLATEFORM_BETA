Introduction to ziiui

ziiui is an open-source collection of production-ready text effects, cursor interactions, scroll-driven sections, and WebGL shaders. Every component is a standalone HTML file — copy it, paste it, ship it.

Get started by picking a component from the sidebar, tweaking it live in the Lab, and copying the generated code into your project. No build step. No package to install. The output runs anywhere a browser can open an HTML file.

Beta. ziiui is under active development. Component APIs may change. Report issues or suggest components on GitHub.

Quick start

Step 01

Pick a component

Browse the sidebar. Components are grouped by category — Text, Cursor, Interactive, Scroll, and Shader.

Step 02

Tweak it live

Use the Controls panel to change text, split mode, or preset. The preview updates instantly.

Step 03

Copy the output

The Generated code panel always shows the exact HTML that produced the preview. Copy it and paste it into your project.

How it works

Each component is defined as a pair of inert templates — CSS and JavaScript. Placeholders like __TEXT__ are replaced with your input at build time. That's the entire pipeline.

The output is a complete, standalone HTML document. Open it in a browser, host it on any static server, or paste it into a CodePen. The only external dependency is the library the effect actually needs — for example, GSAP for scroll effects, or Three.js for shaders — and that is loaded from a CDN at the top of the file.

HTML — structure 
<!-- 1. Base styles -->
<style>
  body { margin: 0; min-height: 100vh; display: flex; }
  #t { font-size: clamp(1.4rem, 6vw, 2.6rem); }
</style>

<!-- 2. The text target -->
<p id="t">Your text here</p>

<!-- 3. The animation -->
<script>
  const el = document.getElementById('t');
  const text = el.textContent;
  el.textContent = '';
  // ...split and animate
</script>

Nothing here is a black box. Swap the text, tweak the numbers, or strip out the reduced-motion guard if you don't need it.

Usage

HTML — copy & paste 
<!-- Paste this into any HTML file -->
<style>
  .u {
    opacity: 0;
    transition: opacity .5s ease;
    transition-delay: calc(var(--i) * .03s);
  }
  .u.on { opacity: 1; }
</style>

<p id="t">Animate your ideas with motion-primitives</p>

<script>
  const el = document.getElementById('t');
  const text = el.textContent;
  el.textContent = '';

  let i = 0;
  text.split(/(\s+)/).forEach(part => {
    if (!part) return;
    if (/^\s+$/.test(part)) { el.append(part); return; }
    const w = document.createElement('span');
    w.className = 'w';
    Array.from(part).forEach(ch => {
      const s = document.createElement('span');
      s.className = 'u';
      s.style.setProperty('--i', i++);
      s.textContent = ch;
      w.append(s);
    });
    el.append(w);
  });

  requestAnimationFrame(() => requestAnimationFrame(() => {
    el.querySelectorAll('.u').forEach(u => u.classList.add('on'));
  }));
</script>
Tip. Every component checks prefers-reduced-motion and skips its animation when needed. Keep that guard in place — it's already included in the output.

Generated output

Every output is a complete, standalone HTML document. Open it in a browser, host it on any static server, or paste the whole thing into a CodePen. The only external dependency is the library the effect actually needs — for example, GSAP for scroll effects, or Three.js for shaders.

Here is a full example of a text effect, ready to copy:

HTML — full standalone file 
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Text Effect</title>
  <style>
    body {
      margin: 0;
      min-height: 100vh;
      display: flex;
      padding: 1rem;
      background: #0f1115;
      color: #f2f2f0;
      font-family: system-ui, sans-serif;
      text-align: center;
    }
    #t {
      margin: auto;
      font-size: clamp(1.4rem, 6vw, 2.6rem);
      font-weight: 600;
    }
    .u {
      opacity: 0;
      display: inline-block;
      transition: opacity .5s ease;
      transition-delay: calc(var(--i) * .03s);
    }
    .u.on { opacity: 1; }
  </style>
</head>
<body>

  <p id="t">Animate your ideas with motion-primitives</p>

  <script>
    const el = document.getElementById('t');
    const text = el.textContent;

    if (!window.matchMedia('(prefers-reduced-motion: reduce)').matches) {
      el.textContent = '';

      let i = 0;
      text.split(/(\s+)/).forEach(part => {
        if (!part) return;
        if (/^\s+$/.test(part)) { el.append(part); return; }
        const w = document.createElement('span');
        w.className = 'w';

          const s = document.createElement('span');
          s.className = 'u';
          s.style.setProperty('--i', i++);
          s.textContent = ch;
          w.append(s);
        });
        el.append(w);
      });

      requestAnimationFrame(() => requestAnimationFrame(() => {
        el.querySelectorAll('.u').forEach(u => u.classList.add('on'));
      }));
    }
  </script>
</body>
</html>

Best practices

  • Respect reduced motion. Every component already checks prefers-reduced-motion and skips its animation when needed. Keep that guard in place.
  • Keep text reasonable. Text effects split into individual characters. A 40-character headline animates beautifully; a 400-character paragraph does not.
  • One hero per page. Cursor, scroll, and shader effects are heavy on GPU and layout. Use one hero-level effect per page — don't stack them.
  • Host the output anywhere. The output is a single HTML file. It works on GitHub Pages, Netlify, Vercel, a WordPress custom HTML block, or a self-hosted server.

FAQ

Do I need to install anything?

No. The output is a standalone HTML file. It loads any required library from a CDN at the top of the file.

Can I use these in a React or Vue project?

Yes. The output is plain HTML, CSS, and JavaScript. Drop it into a component, an iframe, or a custom HTML block.

Can I modify the generated code?

Absolutely. Nothing is minified or obfuscated. Swap the text, change the timings, strip the parts you don't need.

Why does the preview height change?

Each component declares a previewSize of compact or large. Text and cursor effects use a compact preview; scroll, interactive, and shader effects use a larger one.
